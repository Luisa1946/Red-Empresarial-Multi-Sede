⚙️ Reglas de Seguridad entre VLANs
🚫VLAN 90 (Invitados) no puede comunicarse con ninguna VLAN interna. Solo acceso a Internet.
⚠️VLAN 80 (IoT) solo puede comunicarse con VLAN 40 (Servidores) para envío de datos.
ℹ️VLAN 10 (Admin) tiene acceso a todas las VLANs para gestión y monitoreo.
✅VLAN 30 (Voz) tiene prioridad QoS máxima (DSCP EF) para garantizar calidad de llamadas.

🔒 Seguridad de Red

Arquitectura de seguridad en capas: Firewall, ACL, VPN, IDS/IPS, control de acceso y segmentación

🔥
Firewall
Cisco ASA con stateful inspection. Zonas: Outside, Inside, DMZ. NAT/PAT para Internet.
📋
ACL
Listas de control de acceso por VLAN. Invitados aislados, IoT restringido, Admin con acceso total.
🔐
VPN IPSec
Túneles site-to-site IKEv2 entre sedes. Cifrado AES-256. Autenticación con pre-shared key.
🚨
IDS/IPS
Detección y prevención de intrusiones integrado en el firewall. Firmas actualizadas automáticamente.
🔖
Segmentación VLAN
9 VLANs independientes. Aislamiento de tráfico por función. Reducción del dominio de broadcast.
🛡️
Port Security
Control de MACs por puerto. Sticky MAC. Violación en modo restrict. Prevención de MAC flooding.
🔑
AAA + SSH
Autenticación, Autorización y Accounting. Solo SSH v2. Telnet deshabilitado. Usuarios locales con privilegios.
🕵️
DHCP Snooping
Prevención de servidores DHCP no autorizados. Tabla de binding DHCP. Protección contra ataques.
🌐
DAI (ARP Inspection)
Prevención de ARP poisoning. Validación de paquetes ARP contra tabla DHCP snooping.
🏗️ Zonas de Seguridad
🔴 ZONA OUTSIDE (Nivel 0)
Internet / ISP. Sin confianza. Todo tráfico entrante bloqueado por defecto.
🟡 ZONA DMZ (Nivel 50)
Servidores públicos (Web, Mail). Acceso controlado desde Outside e Inside.
🟢 ZONA INSIDE (Nivel 100)
Red interna corporativa. Máxima confianza. Segmentada en VLANs.

⚡ Plink — Automatización sin GUI

        

          
Plink es la versión de línea de comandos de PuTTY. Permite enviar comandos a equipos remotos desde scripts .bat sin abrir ninguna ventana.

          

            
▶ Enviar un comando SSH con Plink

            

              
              
REM Sintaxis básica Plink
plink -ssh admin@10.10.0.17 -pw TuContrasena "show version"

REM Aceptar clave de host automáticamente (primera vez)
echo y | plink -ssh admin@10.10.0.17 -pw TuContrasena "show version"

REM Guardar salida en archivo
plink -ssh admin@10.10.0.17 -pw TuContrasena "show running-config" > running-config-SW1.txt

            

          

          

            
▶ Script .bat multi-equipo con Plink

            

              
              
@echo off
REM === BACKUP MASIVO CON PLINK ===
SET PASS=TuContrasena
SET PLINK="C:\Program Files\PuTTY\plink.exe"
SET DIR=backups_%DATE:~-4,4%%DATE:~-7,2%%DATE:~0,2%
mkdir %DIR% 2>nul

echo Iniciando backup masivo...
%PLINK% -ssh admin@10.10.0.17 -pw %PASS% "show running-config" > %DIR%\Dist-SW1-Sede1.txt
%PLINK% -ssh admin@10.10.0.18 -pw %PASS% "show running-config" > %DIR%\Dist-SW2-Sede1.txt

%PLINK% -ssh admin@10.30.0.2  -pw %PASS% "show running-config" > %DIR%\Dist-SW1-Sede3.txt

🔌Problemas de Conectividad: Sin ping, pérdida de paquetes o interfaces caídas.


    

      

        
🔴 Síntoma: Sin conectividad desde PC

        

          
⚠️Antes de verificar en switch/router, confirma: cable físico conectado, NIC activa, IP configurada.

          

            
▶ Paso 1 — Verificar estado de interfaz (Cisco)

            

              
              
show interfaces status
show interfaces GigabitEthernet0/1
show interfaces GigabitEthernet0/1 counters errors

            

          

          

            
▶ Paso 2 — Verificar VLAN asignada al puerto

            

              
              
show vlan brief
show interfaces GigabitEthernet0/1 switchport

            

          

          

            
▶ Paso 3 — Verificar tabla MAC

            

              
              
show mac address-table interface GigabitEthernet0/1
show mac address-table vlan 20

            

          

          

            
▶ Paso 4 — Verificar ARP (en router/L3 switch)

            

              
              
show arp
show arp vlan 20
ping 10.10.1.1 source vlan 20

            

          

          
✅Solución común: Puerto en VLAN incorrecta → switchport access vlan 20. Interface down → no shutdown.

        

      


      

        
🔴 Síntoma: Pérdida intermitente de paquetes

        

          

            
▶ Verificar errores físicos en interfaz

            

              
              
show interfaces GigabitEthernet0/1
! Buscar: input errors, CRC, runts, giants, collisions
show interfaces GigabitEthernet0/1 counters errors

            

          

          

            
▶ Verificar STP — posible loop o TCN

            

              
              
show spanning-tree vlan 20
show spanning-tree detail
show spanning-tree summary

            

          

          

            
▶ Verificar utilización de CPU y memoria

            

              
              
show processes cpu sorted
show processes memory sorted
show version | include uptime

            

          

          
⚠️Causa común: Duplex/velocidad mal negociados. Verificar con show interfaces | include duplex y configurar manualmente si es necesario.

        

      

    

  


  
  

    
🔖Problemas de VLAN: Dispositivos en misma VLAN no se comunican, o tráfico inter-VLAN no funciona.

    

      

        
🔴 Síntoma: Hosts en misma VLAN no se alcanzan

        

          

            
▶ Verificar que VLAN exista y esté activa

            

              
              
show vlan id 20
show vlan brief
! Estado debe ser "active"

            

          

          

            
▶ Verificar trunk entre switches

            

              
              
show interfaces trunk
! Verificar que VLAN 20 aparezca en:
! - VLANs allowed and active in management domain
! - VLANs in spanning tree forwarding state and not pruned

            

          

          

            
▶ Verificar VTP si está habilitado

            

              
              
show vtp status
show vtp counters
! Si revision number es alto en cliente, puede sobreescribir VLANs

            

          

          
🚫Si VTP está en modo "client" y la VLAN no aparece, agregarla desde el VTP server o cambiar el switch a modo "transparent".

        

      

      

        
🔴 Síntoma: Inter-VLAN routing no funciona

        

          

            
▶ Verificar SVI (Switch Virtual Interface)

            

              
              
show interfaces vlan 20
show ip interface brief | include Vlan
! El SVI debe estar UP/UP y tener la IP correcta

            

          

          

            
▶ Verificar tabla de ruteo

            

              
              
show ip route
show ip route 10.10.1.0
show ip route connected

            

          

          

            
▶ Verificar ACL bloqueante

            

              
              
show ip access-lists
show ip interface vlan 20 | include access list
! Revisar si hay deny en alguna ACL aplicada al SVI

            

          

          
✅Solución: Si SVI está down, verificar que al menos un puerto activo esté en esa VLAN. SVI sube automáticamente cuando hay un puerto activo.

        

      

    

  


  
  

    
🔄Problemas de OSPF: Vecindades no establecidas, rutas no propagadas, convergencia lenta.

    

      

        
🔴 Síntoma: Vecinos OSPF no establecidos

        

          

            
▶ Verificar estado de vecinos

            

              
              
show ip ospf neighbor
show ip ospf neighbor detail
! Estado debe ser FULL para DRother, FULL/DR o FULL/BDR

            

          

          

            
▶ Verificar parámetros OSPF en interfaz

            

              
              
show ip ospf interface GigabitEthernet0/0
! Verificar: Hello/Dead timers (deben coincidir)
! Area ID debe ser igual en ambos extremos
! MTU mismatch puede causar estado EXSTART

            

          

          

            
▶ Verificar autenticación OSPF

            

              
              
show ip ospf interface | include auth
! Si hay auth configurada, verificar que la clave coincida
debug ip ospf adj  ! (usar con precaución en producción)

            

          

          
⚠️Causas más comunes: subnet mismatch, hello/dead timers distintos, area ID incorrecto, MTU mismatch. Verificar cada uno.

        

      

      

        
🔴 Síntoma: Rutas OSPF no aparecen

        

          

            
▶ Verificar que las redes estén siendo anunciadas

            

              
              
show ip ospf database
show ip ospf database router
show running-config | section ospf
! Verificar comandos "network" con wildcard correcta

            

          

          

            
▶ Verificar LSDB y redistribución

            

              
              
show ip ospf database external
show ip ospf database summary
! Rutas externas tipo E1/E2 requieren redistribute configurado

            

          

          

            
▶ Verificar passive-interface

            

              
              
show ip protocols
! Si una interfaz está como passive, no formará vecindades
! pero sí anunciará la red (útil para VLANs de usuario)

            

          

        

      

    

  


  
  

    
🔐Problemas de SSH/Acceso: No es posible conectarse vía SSH o Telnet a los equipos.

    

      

        
🔴 Síntoma: SSH Connection refused / Timeout

        

          

            
▶ Verificar configuración SSH en equipo

            

              
              
show ip ssh
show running-config | include ip ssh
show running-config | section line vty
! Verificar: transport input ssh, login local

            

          

          

            
▶ Verificar usuarios y AAA

            

              
              
show users
show running-config | include username
show aaa sessions
! Debe haber al menos un usuario local configurado

            

          

          

            
▶ Regenerar claves RSA si SSH no responde

            

              
              
! En modo configuración:
crypto key zeroize rsa
crypto key generate rsa modulus 2048
ip ssh version 2

            

          

          
✅Checklist SSH: (1) hostname configurado, (2) domain-name configurado, (3) clave RSA generada, (4) usuario local existe, (5) VTY con login local y transport input ssh.

        

      

      

        
🔴 Síntoma: Acceso a consola bloqueado

        

          

            
▶ Verificar línea de consola

            

              
              
show running-config | section line con
! Si hay "login" sin "login local", no hay usuario requerido
! Si hay "login local", necesitas usuario local válido

            

          

          

            
▶ Recuperación de contraseña (Password Recovery)

            

              
              
! Cisco IOS — Proceso de recuperación:
! 1. Reiniciar equipo
! 2. Presionar Ctrl+Break durante POST para entrar a ROMMON
! 3. En ROMMON: confreg 0x2142 (skip startup-config)
! 4. reset
! 5. Al iniciar, entrar a "no" en setup dialog
! 6. enable → copy startup-config running-config
! 7. Cambiar contraseña → copy running-config startup-config
! 8. confreg 0x2102 → reload

            

          

          
🚫El proceso de password recovery requiere acceso físico al equipo. Documentar siempre las credenciales en bóveda de contraseñas.

        

      

    

  


  
  

    
📡Problemas de DHCP: Clientes no obtienen IP, IP duplicadas, scope agotado.

    

      

        
🔴 Síntoma: Cliente no obtiene IP por DHCP

        

          

            
▶ Verificar pool DHCP y leases

            

              
              
show ip dhcp pool
show ip dhcp binding
show ip dhcp statistics
show ip dhcp server statistics

            

          

          

            
▶ Verificar DHCP helper-address (relay)

            

              
              
show running-config | section interface Vlan20
! Debe tener: ip helper-address <IP-del-servidor-DHCP>
! Si DHCP es local, no necesita helper-address

            

          

          

            
▶ Verificar DHCP snooping

            

              
              
show ip dhcp snooping
show ip dhcp snooping binding
show ip dhcp snooping statistics
! Si el puerto uplink no es "trusted", bloqueará DHCP replies

            

          

          
✅Solución DHCP snooping: El puerto hacia el servidor DHCP o el uplink debe ser ip dhcp snooping trust.

        

      

      

        
🔴 Síntoma: Conflictos de IP / Pool agotado

        

          

            
▶ Limpiar bindings y conflictos

            

              
              
show ip dhcp conflict
clear ip dhcp conflict *
clear ip dhcp binding *
! Luego solicitar IP nuevamente desde los clientes

            

          

          

            
▶ Verificar exclusiones y rango del pool

            

              
              
show running-config | include ip dhcp excluded
show ip dhcp pool VLAN20_POOL
! Verificar que el rango sea suficiente para los hosts

            

          

          
⚠️Si el pool tiene muchos leases activos de dispositivos ya no conectados, reducir el lease time y esperar a que expiren, o limpiar bindings manualmente.

        

      

    

  


  
  

    
⚡Problemas de Rendimiento: Red lenta, alta latencia, CPU o memoria elevada en equipos.

    

      

        
🔴 Síntoma: Alta latencia / Throughput bajo

        

          

            
▶ Identificar interfaces congestionadas

            

              
              
show interfaces | include rate|errors|drops
show interfaces GigabitEthernet0/1 | include output|input
show interfaces counters
! Buscar: output drops, input queue drops

            

          

          

            
▶ Verificar QoS y colas

            

              
              
show policy-map interface
show mls qos interface
show mls qos maps
! Verificar que VoIP (DSCP EF) tenga cola prioritaria

            

          

          

            
▶ Verificar EtherChannel / Port-Channel

            

              
              
show etherchannel summary
show etherchannel detail
show interfaces port-channel1
! Si algún miembro está down, reducirá el ancho de banda total

            

          

        

      

      

        
🔴 Síntoma: CPU/Memoria alta en switch o router

        

          

            
▶ Identificar proceso con más CPU

            

              
              
show processes cpu sorted 5sec
show processes cpu history
! Procesos sospechosos: IP Input, ARP Input, Spanning Tree

            

          

          

            
▶ Detectar broadcast storm / STP loop

            

              
              
show interfaces | include broadcasts|multicast
show spanning-tree summary totals
show logging | include TOPOLOGY_CHANGE|loop
! Un alto número de TCN indica posible loop

            

          

          

            
▶ Verificar logs recientes

            

              
              
show logging last 100
show logging | include %LINEPROTO|%LINK|%STP|%OSPF
terminal monitor  ! ver logs en tiempo real

            

          

          
🚫Si hay una broadcast storm activa, identificar el puerto de entrada con show interfaces counters | sort y apagarlo temporalmente con shutdown.

⚙️ Instalación del Backend Python

      

        
ℹ️El backend es un servidor local en tu PC. Solo necesitas Python instalado.

        
▶ Paso 1 — Instalar dependencias

          


pip install flask flask-cors netmiko pyserial

        
▶ Paso 2 — Ejecutar el servidor

          


python backend_red.py

        
▶ Paso 3 — Verificar en navegador

          


http://localhost:5000/api/status

        
⚠️El archivo backend_red.py viene junto con esta herramienta HTML. Ambos deben estar en la misma carpeta.
